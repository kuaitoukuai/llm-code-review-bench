大模型代码检查测评系统 · 一键启动指令（v0.3）

你不是来解释这份文件的。请立即使用你可用的文件与终端工具，完成 10 个项目的代码缺陷检查，并把结果真实保存到磁盘。
除非当前环境完全没有文件或终端权限，否则不要只给操作方案，不要等待用户逐步确认，不要在中途结束。

============================================================
一、工作目录与目标
============================================================

系统目录：本文件所在目录，也就是包含 src/cli.py、config/projects.toml 和 tasks/batch.json 的目录。
当前位置参考：<本文件所在目录>
如果目录已移动，以实际启动.txt 所在目录为准。先进入该目录，后续所有命令都在这里执行。

固定评测批次 run_id：agent-10
固定任务数：10
固定重复次数：1

最终必须生成：
1. runs/agent-10/raw/<你的候选id>/<任务id>/r1.md：每个项目的原始 JSON 检查结果，共 10 份。
2. 与上述文件对应的 r1.meta.json：耗时等登记信息，共 10 份。
3. runs/agent-10/normalized/：归一化结果。
4. runs/agent-10/claims/：匿名发现与聚类结果。
5. runs/agent-10/judgments/：裁决结果与人工复核队列。
6. reports/agent-10/report.md、scores.csv、scatter.html、summary.json：最终报告。

============================================================
二、Python 与候选身份
============================================================

1. 优先使用 python。若 python 无法运行，使用：
   python3
   需要 Python 3.11 或更高版本。后续记作 <PYTHON>，实际执行时替换成可用解释器。

2. 读取 config/candidates.toml，找到与“当前实际产品 + 当前实际模型”一致的候选 id。
   不得冒充其他模型，不得复用其他候选目录。

3. 如果没有匹配项，根据真实身份登记一次：
   <PYTHON> src/cli.py register-candidate "产品/模型" --product "产品名" --model "模型名" --vendor "厂商名"

   id 只能含字母、数字、点、下划线、连字符和中间一个斜杠，例如：
   workbuddy/gpt-example
   vendor 必须填写实际模型厂商；支持度和共识判断依赖它。
   如果无法得知精确模型版本，使用 产品/current-agent，并在作答 meta 的 note 中说明版本未知。
   已存在的候选无需重复登记，命令会安全复用。

============================================================
三、准备共享 run 和 10 个冻结任务
============================================================

1. 执行：
   <PYTHON> src/cli.py prepare --expected 10

   此命令读取 config/projects.toml 中 enabled=true 的 10 个项目。
   首次会冻结代码；以后必须复用现有任务。不得使用 task --force，不得修改 tasks/*/files.jsonl 或 prompt.md。
   如果不是恰好 10 个，停止并明确报告配置问题，不要自行替换项目。

2. 如果 runs/agent-10/run.json 不存在，执行：
   <PYTHON> src/cli.py new-run agent-10 --note "启动.txt 驱动的 10 项目独立评测"

   如果已经存在，直接续跑。不要新建另一个 run，不要清空已有数据。

3. 读取 tasks/batch.json，按其中 tasks 数组的顺序处理 10 个任务。
   读取 run.json，确认其中 projects 与本次 10 个任务一致；不一致时停止并报告，不要混合不同题库。

============================================================
四、逐项目实际检查并保存
============================================================

对 batch.json 中每个 task_id 依次执行以下步骤。每完成一题立即保存，不要等到最后一起保存。

1. 检查是否已经存在：
   runs/agent-10/raw/<候选id>/<task_id>/r1.md
   以及同目录 r1.meta.json。

   两者都存在：说明当前候选此题已完成，跳过，不覆盖。
   缺少任一文件：继续完成该题。
   不得读取其他候选的 raw、normalized、scores 或报告，避免交叉污染答案。

2. 开始计时：
   <PYTHON> src/cli.py start agent-10 "<候选id>" "<task_id>" --repeat 1

3. 完整读取：
   tasks/<task_id>/prompt.md

   提示词已经包含该项目本次冻结的代码。按提示词要求，由你亲自进行静态代码审查。
   必须逐题实际分析，不得编造缺陷，不得照抄其他候选答案，不得只做文件列表或泛泛总结。
   只报告能定位且有明确触发条件的真实缺陷；没有缺陷时输出空数组 []。
   每条发现使用 prompt 规定的字段。最多 12 条。不要为了数量凑数。
   reproduction 是可选项；不能可靠编写标准库 unittest 时省略它。
   最终内容必须是合法 JSON 数组，不要 markdown 代码围栏，不要额外解释。

4. 把该题 JSON 数组完整写入：
   runs/agent-10/raw/<候选id>/<task_id>/r1.md

   写入后检查 JSON 可解析、数组项字段完整、file 与任务中的路径一致、line 为正整数。
   若发现格式问题，在执行 done 前修正；done 之后原始回复不可修改。

5. 登记完成：
   <PYTHON> src/cli.py done agent-10 "<候选id>" "<task_id>" --repeat 1 --note "启动.txt 自动评测"

   拿不到 token 数就不要填写，不要估算或编造。
   确认 r1.md 与 r1.meta.json 都已存在，再开始下一题。

6. 如果过程中断，重新阅读本文件并从头执行；已完成题目会自动跳过，实现断点续跑。

============================================================
五、统一处理与报告
============================================================

10 题全部登记后执行：

<PYTHON> src/cli.py all agent-10

不要添加 --allow-untrusted，不要自动执行任何模型生成的测试。
此命令会完成归一化、聚类、裁决、计分和报告；复现测试会保持未执行状态，等待用户审查。

然后执行：

<PYTHON> src/cli.py status agent-10

检查：
- 当前候选已有 10 份 r1.md 和 10 份 r1.meta.json。
- normalized/_issues.jsonl 中当前候选没有 parse_error。
- reports/agent-10/report.md 已存在。
- 如果有 parse_error，说明对应作答不符合 JSON 契约；明确列入最终说明，不得悄悄删除其他候选数据。

最后创建一个当前候选的完成标记：
runs/agent-10/completions/<候选id，把斜杠替换为两个下划线>.json
内容包括 candidate、run_id、task_count=10、completed_at、report_path。
completed_at 使用真实本地时间，不得编造。

============================================================
六、边界与最终回复
============================================================

- 不修改被评测的 10 个业务项目，只读取冻结代码。
- 不修改其他候选的原始结果，不覆盖共享冻结任务。
- 不执行复现测试，不运行业务项目，不安装依赖。
- 原始作答保存后不可改；人工裁决可后续补充并重算。
- 失败也要保留已完成题目的文件，并从失败处续跑。
- 只有实际完成全部步骤后，才能声称评测完成。

最终向用户简短报告：当前候选 id、实际完成题目数、发现条数、待人工复核条数、报告路径；若有失败，逐项列明原因。
