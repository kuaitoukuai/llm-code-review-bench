# 02 总体架构

> 这一篇解决"东西放哪、谁读写谁、命令怎么排"。
> 改代码之前看一遍，能避免把可重算的东西写进不可变的层。

## 一、一张图

```
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ 0. 冻结题库（一次性）                                                     │
 │    scan → 选项目 → task 冻结快照（files.jsonl + sha1 + commit）           │
 └───────────────────────────────┬──────────────────────────────────────────┘
                                 ↓
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ 1. 采集（人肉，2 小时）                                                   │
 │    start 计时 → 粘贴 prompt.md → 模型作答 → 存 out.md → done 登记         │
 │    产物：raw/<candidate>/<task>/r<n>.md + r<n>.meta.json（不可变）        │
 └───────────────────────────────┬──────────────────────────────────────────┘
                                 ↓
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ 2. 归一化 normalize                                                       │
 │    抽 JSON → 字段校验 → 超限/缺字段拒收 → normalized/<candidate>/...jsonl │
 │    产物：一行一条 claim，带 raw_ref 回指                                  │
 └───────────────────────────────┬──────────────────────────────────────────┘
                                 ↓
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ 3. 聚类 cluster                                                           │
 │    同文件 + 行号窗口 + 标识符 → clusters.jsonl（带 support_count）         │
 │    产物：pool.jsonl（无来源，给裁判） + origin.jsonl（映射，本地留）      │
 └───────────────────────────────┬──────────────────────────────────────────┘
                                 ↓
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ 4. 裁决（四条通道，可并存）                                               │
 │    a. 执行复现（最硬）：跑模型给的复现测试，跑红即真                      │
 │    b. 人工：human.jsonl 逐行填                                             │
 │    c. 裁判票：packets → 外部裁判 → votes                                   │
 │    d. 共识推断（最软）：多家提出但无票                                     │
 │    产物：verdicts.jsonl（每条带 confidence 与通道来源）                    │
 └───────────────────────────────┬──────────────────────────────────────────┘
                                 ↓
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ 5. 沉淀 bank（v1.0 新增）                                                 │
 │    确认的条目 → bank/<proj>_bank.jsonl（issue_id / verdict / real_sev）    │
 │    新模型 → 撞库 → 命中即得分 → 未命中做增量盲评 → 回写 bank              │
 └───────────────────────────────┬──────────────────────────────────────────┘
                                 ↓
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ 6. 计分 score + 报告 report                                               │
 │    双阶段：raw_score（绝对分） / rate_score（率化分，题库成型后）          │
 │    产物：scores.json / scores.csv / report.md / scatter.html              │
 └──────────────────────────────────────────────────────────────────────────┘
```

关键约束：**箭头只能往下，不能往上**。计分层永远不能回写裁决层，裁决层不能回写归一化层，归一化层不能改原始层。

## 二、六层数据模型

| 层 | 位置 | 内容 | 可变性 | 谁写 | 谁读 |
|---|---|---|---|---|---|
| **L0 题库层** | `tasks/<task>/` | 冻结的代码（`files.jsonl`）+ 拼好的提示词（`prompt.md`）+ 元信息（`meta.json`） | **不可变**（要改就建新 task） | `task` 命令 | `start` / `packets` |
| **L1 原始层** | `runs/<run>/raw/` | 模型原始回复 + 起止时间 + token | **不可变** | `done` 命令 | `normalize` |
| **L2 归一化层** | `runs/<run>/normalized/` | 一行一条 claim，统一字段 | 可重跑 | `normalize` | `cluster` / `score` |
| **L3 匿名层** | `runs/<run>/claims/` | `pool.jsonl`（无来源）+ `origin.jsonl`（映射） | 可重跑 | `cluster` | `packets` / `score` |
| **L4 裁决层** | `runs/<run>/judgments/` | packets / votes / human / exec / verdicts / queue | **可随时补** | `packets` / `votes` / 人工 / `execute` | `score` |
| **L5 计分层** | `runs/<run>/scores.json` + `reports/` | 分数、报表、散点 | 可任意重算 | `score` / `report` | 人 |
| **L6 沉淀层**（新） | `bank/<proj>_bank.jsonl` | 跨 run 的已裁决问题集 | **只追加 + 状态可改** | `bank` 命令 | `score` / `hit` |

L6 是 v1.0 新增的，也是"可复用"的载体。它介于 L4 和 L5 之间：由 L4 的裁决结果喂养，被 L5 的计分消费。

### 为什么 L3 要拆成两个文件

裁判包只能从 `pool.jsonl` 取。`pool.jsonl` 里**没有** `candidate` 字段，也**没有** `support_count` 字段。这不是洁癖，是两个具体偏差的防线：

- 没有 `candidate` → 防自我偏爱（裁判认不出自己）
- 没有 `support_count` → 防从众（裁判不知道"几家都说了"）

`origin.jsonl` 只被 `score` 读，用来把 claim 还原到候选身上。两个文件用 `claim_id` 关联。

## 四、模块职责

### core.py（275 行，v0.1）

- 常量：`SEVERITIES` / `CATEGORIES` / `FIELD_ALIASES` / `SEVERITY_MAP`
- 配置：`load_system` / `load_candidates` / `load_projects`
- IO：`read_jsonl` / `write_jsonl` / `read_json` / `write_json`
- 归一化工具：`norm_severity` / `norm_category` / `norm_line` / `norm_path` / `char_len`
- 解析：`extract_json_block`（从回复里抽 ```json 块）

**v0.2 要加**：`hmac_id(text, salt)`（盐哈希）、`VERSION` 读取、`schema_validate(row)`（集中校验）。

### pipeline.py（1138 行，v0.1）

| 函数 | 职责 | 可重入 |
|---|---|---|
| `new_run` | 建 run 目录与 `run.json` | 否（已存在则报错） |
| `scan_projects` | 扫目录、按 git/体量/测试/新鲜度打分 | 是 |
| `build_task` | 冻结项目成题库 | 否（`--force` 才覆盖） |
| `session_start` / `session_done` | 计时与登记 | 是 |
| `normalize` | 抽 JSON、校验、拒收 | 是（覆盖 normalized） |
| `cluster` | 去重、算支持度、写 pool/origin | 是 |
| `execute_reproductions` | 跑模型给的复现测试 | 是 |
| `make_packets` | 生成裁判包 | 是 |
| `collect_votes` | 回收裁判票 | 是（累加） |
| `adjudicate` | 汇总裁决、导出人工队列 | 是 |
| `score` | 计分 | 是 |

**v1.0 要加**：`score` 增加 `rate_score` 分支；新增 `bank_sync`（run 的 verdicts → bank）。

### bank.py（新增）

```
issue_id(proj, file, line, category)  → 稳定 ID，形如 K-7Q2M
load_bank(proj)                       → 读 jsonl，建内存索引
match(claim, bank)                    → 三层撞库，返回 (issue_id, score, reason)
upsert(proj, issue)                   → 追加或更新 found_by / verdict
recompute_found_by(proj)              → 重算独到归属
```

### anon.py（新增）

```
make_salt(path)          → 生成一次本地盐（32 字节，hex 存 .salt）
anon_id(claim, salt)     → HMAC-SHA256 前 8 位 → 形如 Q2M7
obfuscate(text, level)   → L2 作者混淆（同义替换，只动 claim/impact）
check_leak(claims)       → 自检：原文与匿名文本的相似度，超阈值告警
```

### inject.py（新增）

```
plan(proj, n)        → 按规则挑埋点位置（返回候选：删防御/改边界/漏 await）
apply(proj, plan)    → 在副本上改代码，生成 injected 快照
verify(proj)         → 跑单测，抓到才算合格埋点
golden(proj)         → 生成 golden.jsonl（file/line/severity/expected_test）
```

### report.py（275 行，v0.1）

`build_report` / `_render_md` / `_write_csv` / `_write_scatter`。

**v1.0 要加**：`fix_list.md`（按项目、按严重度排序的待修清单）、双分列、`bank` 命中率小节。

### 新增（本方案）

| 命令 | 版本 | 作用 | 示例 |
|---|---|---|---|
| `anon <run>` | v0.2 | 生成/重建盐哈希 ID 与混淆文本 | `python src/cli.py anon r01 --level L1` |
| `inject plan <proj>` | v0.2 | 生成埋点方案 | `python src/cli.py inject plan t05 --n 4` |
| `inject apply <proj>` | v0.2 | 在副本上埋点并验证 | `python src/cli.py inject apply t05 --dry-run` |
| `bank sync <run>` | v1.0 | 把裁决结果写入 bank | `python src/cli.py bank sync r01` |

命令设计原则：**全部幂等**（除 `new-run` / `task`），重复执行不产生副作用。这样才能"改一个参数，重跑一条命令"。

## 六、一次评测的时序

```
T+0min    new-run r01
T+1min    task t05 / t06 / ... （或提前批量建好）
T+2min    start r01 kimi/kimi-k2.5 t05
T+12min   done  r01 kimi/kimi-k2.5 t05 --from out.md --token-in 45000 --token-out 3200
T+12min   start r01 kimi/kimi-k2.5 t06      ← 同一候选接着下一个项目
   ...
T+100min  10 个项目全部登记完成
T+102min  all r01                            ← normalize → cluster → packets → score → report
T+105min  人工过 queue.md（15–25 条）
T+145min  填 human.jsonl → verdicts → score → report  （重算，不重跑）
T+150min  bank sync r01                      ← 第一次沉淀
```

注意 `all` 里 `packets` 之后会停住等裁判票——如果这一轮不做裁判，直接 `score` 会给"共识推断"级别的结论，也是有效的，只是证据弱一档。

## 七、架构上的三个"不许"

1. **不许在 `normalize` 里改原文。** 想改表述，改到 `claim` 字段里，原文留在 `raw/`。
2. **不许让 `score` 读 `raw/`。** 计分只能读 `verdicts.jsonl` + `origin.jsonl` + `run_logs.jsonl`。否则"改公式重算"就会变成"重新解析一遍"，慢且易错。
3. **不许让裁判包带 `support_count`。** 一旦带上，从众偏差立刻回来，前面所有匿名工作白做。
